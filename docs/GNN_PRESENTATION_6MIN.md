## Slide 3 — 动机：GPT-4o 的四个硬伤（45 秒）

**视觉建议** ：四象限 / 红色 X 图

| 痛点 | 实测 |
|---|---|
| 延迟高 | ~20 秒 / 决策 |
| 成本高 | 30 集烧掉数美元 |
| 离线不可用 | 必须连网调 API |
| 不可复现 | API 抽样，结果不确定 |

**口播：**
"GPT-4o 决策模块有 **四个硬伤**：

第一，**延迟**。每次 API 往返加上图像编码，单次决策要 20 秒左右。
第二，**成本**。每集需要 5 到 10 次决策，跑 30 集就要烧掉几美元——你想做大规模评测、想跑 1000 集消融实验，**根本不可行**。
第三，**离线场景失败**。任何无网络、无 API key 的边缘机器人都没法部署。
第四，**不可复现**。同一输入两次调用结果可能不同，很难写论文做对比。

**核心矛盾**：GPT 是个好老师，但它太贵太慢，根本没法上机。所以我们需要一个**学生模型**，把 GPT 学过的决策知识蒸馏下来。"

## Slide 4 — 为什么选 GNN（40 秒）

**视觉建议** ：画一张二部图 — 左边 2 个机器人节点，右边 5 个 frontier 节点，之间连边

```
        机器人 R = {r1, r2}     ←── 边 E_{r,f}：dx, dy, dist, cos_align
        前沿   F = {f1, ..., fk}     ──→  描述相对位姿
```

**口播：**
"那为什么用 GNN？因为这个问题**天然就是一张图**。

左边是 2 个机器人节点，右边是若干 frontier 节点；它们之间的关系——相对距离、对齐角度——比节点本身的特征更重要。

更关键的是有三个性质：
1. **节点数量是变的** —— 每个时刻 frontier 数量在 3 到 10 个之间变化；
2. **关系建模是核心** —— 决定 r1 该去 f3 的，是 r1-f3 这条边的属性；
3. **协同约束** —— 两个机器人不能同时撞向同一个 frontier。

MLP 必须 padding 到固定大小，浪费且不优雅；CNN 不适合无网格图。
**Graph Attention 才是天然契合的归纳偏置。**"

## Slide 5 — 方案与系统架构（50 秒）

**视觉建议** ：贴报告 §2.1 的那张 ASCII 架构图（或重画成漂亮版）

**口播：**
"我采用的方案是 **Plan A：Behavior Cloning of GPT**——在 BC、DAGGER、RL 三个候选中选最快出成果的。

整体架构非常简洁：在原系统的决策模块上插了一个**切换开关** ——通过命令行参数 `--nav_mode {gpt | gnn}` 一键切换。

GPT 路径不变，但是我**透明地在它的决策上挂了一个钩子**——只要设置环境变量 `GNN_TRACE_DIR`，每次 GPT 决策就会自动把输入特征 + GPT 选的 frontier 索引落盘成 JSONL。

GNN 路径加载离线训练好的 PyTorch 权重，**输入输出格式与 GPT 完全一致**，所以主循环几乎零改动。

**关键设计原则：统一接口 + 渐进替换 + 降级保护**——如果 GNN ckpt 加载失败，自动 fallback 到最近 frontier 启发式，系统永远不崩。"

## Slide 6 — 模型原理（55 秒）

**视觉建议** ：左侧画特征张量维度，右侧画 Cross-Attention 结构

**特征构造（graph_builder.py）**：
- robot_feat: `(R, 5)` = [x, y, cos(yaw), sin(yaw), num_frontiers]
- frontier_feat: `(F, 5)` = [x, y, score, area, idx]
- edge_feat: `(R, F, 4)` = [dx, dy, dist, cos_align]

所有坐标归一化到 [0,1]，分辨率无关。

**模型（CrossAttentionAssigner）**：
```
Robot tokens (R, H)    Frontier tokens (F, H)
       │                       │
       ├── r2f attention ──────┤   robot 查询 frontier
       │                       │
       ├── f2r attention ──────┤   frontier 查询 robot（建模占用约束）
       │                       │
       └── score_head → logits (R, F) → argmax_F
```

**口播：**
"模型原理分两层：

**第一层是特征构造**。我把每个时刻的地图变成三个张量：机器人节点特征 5 维（坐标 + 朝向 + frontier 数）；前沿节点特征 5 维（坐标 + 显著性分数 + 面积）；以及 R×F 条边的边特征 4 维（相对位移、距离、机器人朝向与边方向的余弦对齐）。

**`cos_align` 这一维特别关键** —— 它给模型一个物理先验：朝向自己当前方向的 frontier 更省力，机器人不必转身。

**第二层是模型**：两层 cross-attention。先做 **r2f attention**——机器人 query frontier，决定它最关心哪些前沿；再做 **f2r attention**——frontier query 机器人，**这一步天然建模了协同约束**：如果某个 frontier 已经被 r1 强烈关注，r2 就该看到这个信号、避开它。最后拼出 R×F 的 score 矩阵，每台机器人 argmax 选自己的 frontier。

整个模型 **不到 10 万参数**，比 GPT-4o 小七个数量级；GPU 推理 **3 毫秒** 完成。"

## 备用 Q&A 弹药

**Q：GNN val_acc 只有 52%，为什么还能在 SR 上追平 GPT？**
A：决策容错性高——多个 frontier 中往往有 2-3 个都能引向目标，前向匹配率不必到 90%；GNN 的归纳偏置（cos_align、最近距离）保证它即使没"模仿对"，选的也是合理 frontier。

**Q：为什么 wall-clock GPT vs GNN 差不多（47 vs 49 分钟）？**
A：因为 30 集中 95% 的时间花在仿真器步进上，决策只占 2%。GNN 真正的延迟优势会在**实机在线运行**和**大规模评测**场景爆发。

**Q：是 GNN 还是 Transformer？**
A：本质是 **Graph Attention Network**——用注意力做消息传递，节点是机器人/frontier，边特征显式输入。形式上等价于一个 2 层、二部图的 GAT。

**Q：为什么不用 torch_geometric？**
A：图太小（节点 < 20），手写注意力更轻、依赖更少、部署更友好。

**Q：协同约束怎么保证两个机器人不撞同一 frontier？**
A：当前用 f2r attention 软约束 + 推理时按 robot 顺序贪心 argmax。后续可加多机互斥 loss 或匈牙利分配。

**Q：和直接用 RL 比有什么优势？**
A：BC 是 cold start，无需 reward shaping、几千样本就能学；RL 需要数百万 episodes 且不稳定。BC + DAGGER + RL 是渐进路线。

## 演讲技巧建议

1. **强对比开场** ：第一句话直接给"6100×"或"100K vs 1T"这种大数字，抓住听众。
2. **Slide 5 架构图建议放大** ，留 5-10 秒让观众看清"GPT 和 GNN 走同一接口"。
3. **Slide 6 边讲边指特征张量** ，避免观众迷失在维度数字里。
4. **Slide 9 用 log 坐标** ，否则 3 ms 那条柱子会看不见。
5. **结尾不要用"That's all"** ，用"Thank you, and I welcome questions on the trade-offs."
6. **预演时严格掐时间** ，可在每张 slide 的备注里写"目标 ≤ X 秒"。
